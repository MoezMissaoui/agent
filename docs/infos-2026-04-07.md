# Rapport d’architecture — Assistant / RAG (état du code)

Analyse du dépôt **Synapse IA** : Control Plane (`saas/backend` NestJS + MySQL), Data / AI Plane (`agent/` FastAPI + Chroma). Dans ce projet, l’« assistant » métier correspond à l’entité **`Agent`** côté base de données (pas le nom de table « assistant »).

---

## 1. Modèle de données et contraintes métier

### Où est défini le modèle « Assistant » ?

- **Entité principale** : `saas/backend/src/database/entities/agent.entity.ts`, table SQL **`agents`** (TypeORM).
- Le schéma MySQL est piloté par TypeORM (`synchronize` hors production dans `database.module.ts`).

### Champs exacts de l’entité `Agent`

| Champ (TypeORM) | Colonne SQL | Description |
|-------------------|-------------|-------------|
| `id` | `id` | Clé primaire auto-incrémentée (`int`) |
| `identifier` | `identifier` | UUID public (36 car.), unique |
| `userId` | `user_id` | FK vers `users.id` |
| `name` | `name` | Nom |
| `description` | `description` | Texte nullable |
| `systemPrompt` | `system_prompt` | Texte nullable (**non exposé par les DTOs API actuels**, voir synthèse) |
| `isActive` | `is_active` | Booléen, défaut `false` |
| `createdAt` | `created_at` | Horodatage création |
| `updatedAt` | `updated_at` | Horodatage mise à jour |

Relations : `documents`, `chatSessions`, `apiKeys`.

### `created_at` et `updated_at`

- **Oui** pour l’assistant : `@CreateDateColumn({ name: 'created_at' })` et `@UpdateDateColumn({ name: 'updated_at' })` sur `Agent`.

### Limite de **3 assistants par client**

- **Aucune logique métier identifiée** qui compte les agents par utilisateur et bloque la création au-delà de 3.
- `AgentsService.create()` (`saas/backend/src/agents/agents.service.ts`) crée un agent sans vérifier un plafond.
- La constante **`3`** présente ailleurs concerne les **jetons d’API par assistant** (`MAX_AGENT_API_ACCESS_TOKENS = 3` dans `saas/backend/src/agent-api-keys/agent-api-keys.service.ts`), pas le nombre d’assistants.

## 2. Ingestion des données (fichier `.txt`)

### Upload et lecture du `.txt`

1. **Control Plane** : `POST .../agents/:agentId/documents/ingest` — `saas/backend/src/agent-ingest/agent-ingest.controller.ts` (multer mémoire, fichier requis).
2. **Service** : `AgentIngestService.ingestDocument()` — `saas/backend/src/agent-ingest/agent-ingest.service.ts` : vérifie extension `.txt` ou `.pdf`, résout user/agent, appelle le Data Plane `POST {DATA_PLANE_BASE_URL}/internal/v1/documents/ingest` avec `user_id`, `agent_id` et le fichier.
3. **Data Plane** : `agent/app/api/routes/documents.py`, fonction `ingest_document` : lit le fichier, crée un job, lance en tâche de fond `_ingest_task` → **`ingest_file_bytes`** dans `agent/app/services/ingestion.py`.

Pour un **`.txt`**, le texte est lu via **`_extract_txt(data: bytes)`** (`utf-8`, `errors="replace"`).

### Text splitter

- **`langchain_text_splitters.RecursiveCharacterTextSplitter`** (`agent/app/services/ingestion.py`).

### `chunk_size` et `chunk_overlap`

- **`chunk_size=1000`**
- **`chunk_overlap=150`**

### Modèle d’embedding avant insertion dans Chroma

- Configuration : `agent/app/core/config.py` — `embedding_model: str | None = None`.
- Implémentation : `agent/app/services/chroma.py`, fonction `_embedding_function()` :
  - Si **`EMBEDDING_MODEL`** est défini : `SentenceTransformerEmbeddingFunction(model_name=settings.embedding_model)`.
  - Sinon : **`DefaultEmbeddingFunction()`** de Chroma (modèle par défaut du client Chroma ; le dépôt ne fixe pas explicitement le nom du modèle dans le code lorsque cette branche est utilisée).

## 3. Stockage et isolation (Chroma DB)

### Configuration de la connexion

- Client : **`chromadb.PersistentClient(path=settings.chroma_persist_path)`** — `agent/app/services/chroma.py`, fonction `get_collection()`.
- Paramètres : `agent/app/core/config.py` — `chroma_persist_path` (défaut `./chroma_data`), `global_collection_name` (défaut `global_rag_collection`).
- **Docker** : `docker-compose.yml` monte `./agent/chroma_data` et définit `CHROMA_PERSIST_PATH: /data/chroma` pour le service `agent`.

### Isolation des données

- **Une collection globale** nommée `global_rag_collection` : tous les chunks y sont stockés.
- Chaque chunk porte des **métadonnées** `user_id`, `agent_id`, `filename` (voir `ingest_file_bytes` dans `ingestion.py`).
- Les requêtes de chat appliquent un filtre **`where`** construit par **`tenant_where(user_id, agent_id, source_filename?)`** — `agent/app/services/chroma.py` : condition `$and` sur `user_id` et `agent_id` (et `filename` si filtre documentaire).
- La requête **`collection.query(..., where=where)`** dans `agent/app/api/routes/chat.py` limite la recherche sémantique au tenant.

**Garanties** : l’isolation repose sur la **cohérence des identifiants** passés au Data Plane et sur le **filtrage métadonnées** à chaque requête. La sécurité entre tenants suppose que les appels internes ne soient pas abusés (ex. **`X-API-Key`** optionnel sur `/internal/v1` si `INTERNAL_API_KEY` est défini — voir config agent).

## 4. Récupération (retrieval) et génération

### Où interroge-t-on Chroma avec la question ?

- Route **`POST /internal/v1/chat`** — `agent/app/api/routes/chat.py`, fonction `chat`.
- Texte d’embedding pour la recherche : produit par **`resolve_retrieval_and_question()`** — `agent/app/rag/query.py` (concaténation des tours user de l’historique + question courante).

### Nombre de morceaux récupérés (`top_k` / `n_results`)

- **`n_results=settings.rag_n_results`** passé à `collection.query`.
- Défaut dans `config.py` : **`rag_n_results: int = 15`** (variable d’environnement **`RAG_N_RESULTS`** dans `agent/.env.example`).

Ensuite, **`apply_context_char_budget()`** — `agent/app/rag/context.py` — tronque la liste de chunks pour respecter **`rag_max_context_chars`** (défaut **280_000** caractères), dans l’ordre renvoyé par Chroma.

### Construction du prompt et rôle du « system prompt »

- **Instructions système** : `build_full_rag_system_prompt()` — `agent/app/rag/prompts.py`. Elles décrivent le périmètre (nom/description agent) et les règles RAG/salutations/hors-sujet. **Le contexte documentaire n’est pas injecté dans le message `system` dans ce code.**
- **Contenu utilisateur** côté OpenAI : `generate_openai_rag_reply()` — `agent/app/rag/openai.py` :
  - joint les chunks avec `"\n\n---\n\n"`,
  - appelle **`build_rag_user_content(context_text, query)`** qui produit un bloc du type :

```text
CONTEXTE RÉCUPÉRÉ :
{contexte}

QUESTION DE L'UTILISATEUR :
{query}
```

  - Les messages envoyés à l’API sont : `[system: system_prompt]`, puis **historique**, puis **un dernier message `user`** avec ce bloc (donc le **contexte RAG est dans le message utilisateur**, pas dans le system prompt).

### Modèle OpenAI pour la réponse

- **`settings.openai_model`**, défaut **`gpt-4o-mini`** (`agent/app/core/config.py`, `agent/.env.example`).
- **Important** : le routeur LLM — `agent/app/rag/llm_router.py` — utilise OpenAI **uniquement si** `LLM_PROVIDER=openai` (`settings.llm_provider`). Sinon, c’est **Gemini** (`gemini-2.5-flash` par défaut). Le compose ne force pas `LLM_PROVIDER` dans l’extrait analysé ; la valeur effective dépend du fichier `agent/.env`.

## Synthèse — écarts ou incomplets par rapport aux exigences

| Exigence | État dans le code |
|----------|-------------------|
| Maximum **3 assistants par client** | **Non implémenté** côté création d’agent ; seule la limite de **3 jetons API par assistant** existe. |
| Assistant = LLM OpenAI | **Configurable** ; défaut actuel du fichier d’exemple : **Gemini**, pas OpenAI. |
| RAG sur fichiers `.txt` | **Oui** ; le pipeline accepte aussi **PDF** (extraction PyMuPDF `fitz`). |
| `system_prompt` en base (`agents.system_prompt`) | Colonne présente mais **jamais lue** dans les services chat/ingest parcourus ; les DTOs create/update **ne l’exposent pas**. |
| Contexte dans le « System Prompt » | Les instructions système **ne contiennent pas** le contexte récupéré ; le contexte est dans le **dernier message user** (pattern valide pour l’API Chat Completions). |
| Horodatages | **`created_at` / `updated_at`** sur `Agent` ; entité **`Document`** : **`created_at` uniquement** (pas de `updated_at`). |
| Isolation Chroma | **Filtrage `user_id` + `agent_id`** sur une collection partagée ; pas de collection physique par tenant. |
